# YOLO Car Counter

Учебный Python-проект для подсчёта транспорта на видео с помощью YOLO26 и
ByteTrack. В проекте есть консольный запуск и адаптивное оконное приложение
на PySide6 + Qt Quick/QML.

## Как работает проект

Для каждого кадра YOLO обнаруживает объекты, а ByteTrack сохраняет уникальный
идентификатор объекта между кадрами. Подсчёт использует одну линию у нижнего
края кадра и нижнюю точку рамки — место, где машина соприкасается с дорогой.
Если трек временно теряется рядом с линией, траектория и направление движения
проверяются прогнозом выхода. Поэтому машина может появиться сбоку или уже
ниже прежней стартовой зоны и всё равно попасть в результат.

## Режимы подсчёта

В проекте есть четыре режима:

- `all` — велосипед, легковой автомобиль, мотоцикл, автобус и грузовик;
- `cars` — только легковые автомобили;
- `two_wheelers` — велосипеды и мотоциклы;
- `heavy` — автобусы и грузовики.

У стандартных COCO-весов нет отдельного класса `moped`, поэтому мопеды
обрабатываются как `motorcycle`. При необходимости группы классов можно
изменить в `config/default.yaml`.

## Установка в Windows PowerShell

Из корня проекта выполните:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

В проекте должны находиться:

```text
YOLO-models\yolo26s.pt
YOLO-models\yolo26n.pt
car_traffic_video\car_traffic.mp4
```

## Запуск

### Оконное приложение

Запуск адаптивного интерфейса из корня проекта:

```powershell
.\.venv\Scripts\python.exe desktop_app.py
```

На главном экране можно выбрать видео, модель, режим и запустить анализ. Во
время обработки в окне отображается размеченный кадр с рамками, ID треков и
одной полупрозрачной линией подсчёта. Большой счётчик и три категории
транспорта обновляются синхронно с воспроизведением результата.

Анализ и воспроизведение разделены ограниченным буфером примерно на 10 секунд.
Анализатор может заранее подготовить кадры, а интерфейс показывает их с ровным
таймером до 30 FPS. Если инференс на конкретном компьютере медленнее исходного
видео, буфер не ускоряет сам YOLO, но полностью устраняет вспышки и рывки от
быстрой выдачи кадров.

Для использования GTX 1650 в окружении должен быть установлен CUDA-вариант
PyTorch. Проверить активное устройство можно так:

```powershell
.\.venv\Scripts\python.exe -c "import torch; print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
```

При `device: auto` приложение использует CUDA, если она доступна, иначе работает
на CPU.

В оконной версии по умолчанию выбран режим `all`, чтобы сразу показывать
разбивку результата. На узком окне боковая навигация автоматически заменяется
нижним меню. На странице «Настройки» можно изменить положение единственной
линии подсчёта в процентах высоты кадра.

Для автоматического старта или короткой проверки:

```powershell
.\.venv\Scripts\python.exe desktop_app.py --autostart --max-frames 300
```

Результаты оконного запуска сохраняются в `outputs\gui`.

### Консольное приложение

Запуск с видео и режимом из конфигурации:

```powershell
.\.venv\Scripts\python.exe run.py
```

Запуск с абсолютным путём к другому видео:

```powershell
.\.venv\Scripts\python.exe run.py --video "C:\Videos\traffic.mp4"
```

Выбор режима через командную строку:

```powershell
.\.venv\Scripts\python.exe run.py --mode all
.\.venv\Scripts\python.exe run.py --mode cars
.\.venv\Scripts\python.exe run.py --mode two_wheelers
.\.venv\Scripts\python.exe run.py --mode heavy
```

Также можно явно указать модель и папку результатов:

```powershell
.\.venv\Scripts\python.exe run.py `
  --video "C:\Videos\traffic.mp4" `
  --model "C:\Models\yolo26s.pt" `
  --mode heavy `
  --output-dir "outputs\experiment-01"
```

Для короткой проверки можно обработать только первые кадры:

```powershell
.\.venv\Scripts\python.exe run.py --max-frames 300 --show
```

Нажатие `Q` в окне остановит обработку.

## Конфигурация

Основные параметры находятся в `config/default.yaml`:

- `modes` — группы классов для режимов;
- `counting.mode` — режим по умолчанию;
- `runtime.confidence` — порог уверенности YOLO;
- `runtime.image_size` — размер изображения для инференса YOLO; в проекте выбран
  баланс `768` для YOLO26s;
- `runtime.tracker` — трекер, по умолчанию `bytetrack.yaml`;
- `runtime.preview_buffer_seconds` и `runtime.playback_fps` — размер буфера и
  скорость воспроизведения предпросмотра;
- `counting.finish_line_y` — единственная линия подсчёта как доля высоты кадра;
- `counting.exit_margin_y` — зона, в которой разрешён прогноз пересечения при
  кратковременной потере трека;
- `counting.max_missing_frames` и `counting.min_track_observations` — защита от
  ложных подсчётов коротких или нестабильных треков.

Например, значение `0.90` означает линию на 90% высоты изображения от верхнего
края.

## Результаты

После запуска в папке `outputs` создаются:

- `*_annotated.mp4` — видео с рамками, ID объектов и линиями;
- `*_events.csv` — список объектов, достигших линии или подтверждённо вышедших
  из нижней зоны; поле `reason` показывает способ подсчёта;
- `*_summary.json` — итоговое количество, выбранный режим и параметры запуска.

## Проверка

Тесты проверяют логику пересечения линий и выбор режимов без запуска нейросети:

```powershell
.\.venv\Scripts\python.exe -m pytest
```

Видео и веса модели являются входными данными проекта. Сгенерированные
результаты и виртуальное окружение в Git не добавляются.
